## Context

Film Studio 的镜头执行包包含完整提示词、模型/规格、人物/场景/道具/风格及首帧职责。已有 operation 支持 submitting、submitted、downloaded、imported 和 abandoned，可继续作为唯一生成账本，不另造队列或审核状态机。

## Decisions

- MCP 只负责即梦协议；Film Studio 负责业务门禁、批准素材边界、媒体下载与导入。通过标准本地 MCP 传输集成，不在 Film Studio 复制即梦请求代码，不修改第三方 Harness。
- 导演只接触 Film Studio 的当前项执行工具。工具从已导出的执行包取参数，不接受模型自由生成的上传路径、URL、提示词替代值或生成数量。
- 生成与查询分离，查询一次返回当前状态；不把长时间轮询挂在单次工具调用中。
- 请求前保存 operation；拿到任务身份后保存提交结果。连接不确定时保留 submitting，必须恢复同一任务或由用户显式放弃，不能自动重提。
- 增加机器可读 MCP 结果供程序消费，避免解析中文展示文本、正则抓取任意 URL 或把视频封面当成视频。
- 图片每次只请求一张。视频只提交当前镜头。结果身份、类型或数量异常时不导入、不补生成。
- 参考图真实路径必须在当前项目已导入的批准素材内。下载只接受服务端任务返回的可信媒体地址，限制协议、重定向、文件大小和输出目录，再复用媒体校验。
- 本地凭据不经 LLM 读取；不采集浏览器 Cookie，不自动购买、领取积分或绕过审核。已在浏览器提交的未完成任务不能伪装成 MCP 新任务或自动放弃。
- 新电影仅展示已明确支持的模型/参数组合。已有项目保留原选择，遇到不支持的能力给出明确提示。
- 普通镜头用图片全能参考；`usePreviousLastFrame=true` 用真实首帧字段，输入仅上一镜当前已批准 take 的尾帧。原镜头设计参考全部保留在 `designReferences`（不上传、不分配 @图片 编号），作者用它们检查身份/场景/道具并提炼必要描述。镜头表审批、上下文、执行包、UI 和 operation 均明确模式，不把首帧改成普通图片参考。切场/换装/新增关键主体不自动改模式，交回镜头设计审核。
- 首帧文本必须包含“首帧”且没有未绑定媒体编号；MCP 拒绝首帧与全能参考混用。提交前检查尾帧已批准、存在且真实路径位于当前项目。operation 保存来源镜头、take、源视频 SHA 和尾帧路径；仍用原 UUID 恢复。

## Protocol evidence

2026-09-03 核对当前即梦模型配置与官方网页 `90.a82fc03ebf.js`：Seedance 2.0/2.5 的 input_media_type 分别列出 unified_edit、first_frame、end_frame；featureManager 在 firstLastFrames / omniReference 切换时重置另一模式输入，不能据通用序列化 schema 同时含两个字段就假定支持混用。首帧请求使用 video_gen_inputs.first_frame_image 和普通 prompt；全能参考使用 unified_edit_input 的 material_list / meta_list。离线协议测试捕获这两条请求，未为探测组合而消费额度。

## Risks / Trade-offs

- 即梦使用内部网页协议，配置可用不代表账号必然有权限；离线测试不能替代真实生成验证。
- 老任务可能没有可用于 MCP 查询的任务 ID，需保留记录并由用户处理，不为兼容旧数据增加自动猜测或重生成逻辑。
- 参考式视频不等同于严格首帧控制：需要依据执行包职责选择真实支持的模式，不能把硬性首帧约束默默降为普通参考。
