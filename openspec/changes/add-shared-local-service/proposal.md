# 按需启动的共享即梦服务

## Why
多个本机项目需要复用即梦登录态和账号并发额度，现有 stdio 子进程无法统一排队或跨项目防止重复提交。

## What Changes
- 增加每项目 stdio 入口 shared-client，由调用方首次使用时启动本机共享 Streamable HTTP 服务。
- 服务只监听回环地址，通过私有注册文件自动发现；调用项目使用 JIMENG_PROJECT_ID 标识。
- 共享浏览器登录、持久化任务与全局生成并发；重复 submitId 返回原回执，参数或项目冲突拒绝。
- 重启只查询 submitting/unknown 状态，不重放生成请求；并发包含上游处理中任务。
- 服务在客户端退出或空闲时继续运行，只通过手动停止或系统退出结束。
- Film Studio 默认使用共享入口，保留显式配置旧 stdio 入口的兼容性。
- SDK 对齐到 1.28 与 Zod 3.25，修复旧 HTTP 错误响应悬挂；校验错误使用标准 isError 回执，现有安全拒绝与零提交检查保留。

## Authorization
用户已要求实施第二种方案，并明确由调用方启动、空闲后不自动退出；本提案落实该授权范围。

## Impact
新增 shared-service 能力；不改变既有 stdio 工具。仅本机单账号，素材使用本机绝对路径。
